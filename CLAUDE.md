# MobiPoint — лендінг магазину мобільних аксесуарів

Інструкція для ШІ-агента, який працює з цим проєктом. Прочитай її перед будь-якими змінами.

## Що це за проєкт

Односторінковий лендінг (one-page) для офлайн-магазину мобільних аксесуарів **MobiPoint** у м. Кременчук: чохли, захисні скла, зарядки, кабелі, навушники, powerbank. Мета сторінки — розповісти про магазин, показати асортимент і точку, умови обміну/доставки, графік роботи та зібрати звернення через форму зворотного зв'язку. Онлайн-кошика й оплати **немає**.

- Мова інтерфейсу та контенту — **українська** (`<html lang="uk">`, `og:locale` = `uk_UA`). Весь новий текст, підписи, `aria-label`, повідомлення про помилки та коментарі в коді пиши українською.
- Валюта — гривня (`₴`), часовий пояс — `Europe/Kyiv`, телефони у форматі `+38 (0XX) XXX-XX-XX`.

## Стек і запуск

- Чистий статичний сайт: **HTML + CSS + vanilla JS**. Без фреймворків, без збирача, без `package.json`, без залежностей npm.
- Зовнішні ресурси: лише шрифт Inter з Google Fonts (з кирилицею) та iframe карти OpenStreetMap.
- Запуск: відкрити `index.html` у браузері або підняти будь-який статичний сервер з кореня проєкту, наприклад:
  ```bash
  python -m http.server 8080
  ```
- Тестів, лінтерів і CI немає. Перевірка — вручну в браузері (див. «Чекліст перевірки»).
- Проєкт **не є git-репозиторієм**. Не ініціалізуй git і не створюй комітів без прохання користувача.

**Не додавай** React/Vue/Tailwind/jQuery, бандлери, TypeScript чи npm-залежності без явного запиту користувача. Якщо задачу можна розв'язати нативними засобами — розв'язуй нативно.

## Структура файлів

```
index.html            — уся сторінка лендінгу (усі секції, lightbox, JSON-LD)
privacy.html          — шаблон політики конфіденційності (noindex)
assets/css/style.css  — усі стилі, mobile-first
assets/js/main.js     — уся інтерактивність (один IIFE)
robots.txt, sitemap.xml
```

Папки `assets/img/` поки **не існує** — фото замінено заглушками (див. «Галерея»). Якщо додаєш зображення, клади їх у `assets/img/…` (галерея — `assets/img/gallery/`), формат `webp`, з `width`/`height`, `alt` і `loading="lazy"`.

## Секції `index.html` (у порядку на сторінці)

| id | Секція | Що всередині |
|---|---|---|
| `header` | Шапка | логотип, меню `#nav`, кнопка дзвінка, бургер `#burger` |
| `home` | Hero | заголовок, лід, CTA-кнопки, статус «відчинено/зачинено», декоративний телефон |
| `about` | Про компанію | текст, 4 переваги `.feature`, лічильники `.stats` з `data-count` |
| `brands` | Бренди | сітка `.brand` (поки текстові назви замість логотипів) |
| `gallery` | Галерея | таби-фільтри `.tab[data-filter]`, плитки `.gallery__item[data-category]` |
| `team` | Команда | картки `.person` з ініціалами замість фото |
| `policies` | Умови | акордеон: обмін, повернення, доставка й оплата |
| `hours` | Робочі години | таблиця `.hours` з `tr[data-day]`, статус роботи |
| `contacts` | Контакти | адреса, телефон, e-mail, месенджери, карта, форма `#contact-form` |

Пункти меню в шапці посилаються на `#id` секцій; підсвічування активного пункту працює через `IntersectionObserver` по `href` лінків `.nav__link`. Додаючи нову секцію в меню — додай і `<section id>`, і `<a class="nav__link">`.

## CSS-конвенції (`assets/css/style.css`)

- **Mobile-first**: базові стилі — для телефона, розширення через `@media (min-width: 480px | 768px | 1024px)` у блоці «Брейкпоінти» в кінці файлу. Десктопне меню вмикається з 1024px.
- **Дизайн-токени** — CSS-змінні в `:root` (`--bg`, `--bg-alt`, `--surface`, `--text`, `--muted`, `--border`, `--accent`, `--accent-2`, `--danger`, `--ok`, `--radius`, `--shadow`, `--header-h`, `--font`). Використовуй їх замість «сирих» кольорів. Новий колір — спершу додай токен.
- **Темна тема** — автоматично через `@media (prefers-color-scheme: dark)`, що перевизначає токени. Будь-який новий компонент має коректно виглядати в обох темах (тобто брати кольори з токенів).
- **Іменування — BEM-подібне**: блок `.gallery`, елемент `.gallery__btn`, модифікатор `.btn--ghost`. Стани — класи `is-*` (`is-open`, `is-active`, `is-scrolled`, `is-visible`, `is-today`, `has-error`).
- Основні компоненти: `.btn` (+ `--ghost`, `--small`, `--block`), `.container` (+ `--narrow`), `.section` (+ `--alt` для чергування фону), `.section__head` з `.eyebrow` + `h2`, `.note` для дрібних приміток.
- Анімації: клас `.reveal` додається з JS; все має вимикатися в `@media (prefers-reduced-motion: reduce)` — не ламай цей блок.
- Стилі коментуються заголовками-роздільниками `/* ---------- Назва ---------- */`. Дотримуйся цього.

## JS-конвенції (`assets/js/main.js`)

- Увесь код у одному IIFE з `'use strict'`. Стиль — **ES5**: `var`, `function`, без стрілочних функцій, `let/const`, модулів і класів. Пиши новий код у тому ж стилі.
- Хелпери: `$(selector, ctx)` і `$$(selector, ctx)` (повертає масив).
- Кожен модуль — окремий блок із коментарем `/* ---------- Назва ---------- */`.
- **Конфіг** на початку файлу — об'єкт `CONFIG`:
  - `timeZone` — `'Europe/Kyiv'`;
  - `hours` — графік (`0` = неділя … `6` = субота, `null` = вихідний, `[відкриття, закриття]` у цілих годинах);
  - `formEndpoint` — URL обробника форми (`https://api.web3forms.com/submit`);
  - `web3formsKey` — Access Key Web3Forms (публічний). Порожній → форма показує помилку й пише попередження в консоль. Демо-режиму немає.
- Модулі: рік у футері, стан шапки при скролі + кнопка «Нагору», бургер-меню (закривається по Esc і кліку на пункт), scroll-spy меню, reveal-анімації + лічильники (`Intl.NumberFormat('uk-UA')`), фільтр галереї, lightbox (клавіатура ←/→/Esc, свайп, повернення фокусу), акордеон (одночасно відкритий лише один пункт), статус «Зараз відчинено/зачинено» (оновлюється щохвилини), валідація й відправка форми.
- Скрипт підключено з `defer` наприкінці `body`; він очікує, що всі елементи з `id` (`#header`, `#to-top`, `#burger`, `#nav`, `#lightbox`, `#contact-form` тощо) існують. Видаляючи/перейменовуючи такі елементи в HTML — онови JS.

## Форма зворотного зв'язку

- Поля: `name` (≥2 символи), `contact` (телефон або e-mail, перевірка регулярками `phoneRe`/`emailRe`), `topic` (select), `message` (≥10 символів), чекбокс згоди `agree` з посиланням на `privacy.html`.
- Валідація на JS (`novalidate` на формі), правила — в об'єкті `rules`, ключ = `id` поля. Помилка виводиться в `<small class="error" data-error-for="id">`, полю ставиться `aria-invalid`, обгортці `.field` — `has-error`. Нове обов'язкове поле = нове правило в `rules` + `<small class="error">` у розмітці.
- Антиспам — honeypot-поле `website` у прихованому `.hp`. Не видаляй його й не робь видимим.
- Відправка: через **Web3Forms** — заявки приходять листом на пошту власника. `POST` JSON на `CONFIG.formEndpoint` з полями `access_key`, `subject`, `from_name`, `replyto` (лише якщо клієнт вказав e-mail) і полями заявки з **українськими ключами** (`Ім'я`, `Контакт`, `Тема`, `Повідомлення`) — саме так вони відображаються в листі. Успіх = `r.ok && data.success`; запит обривається через 15 с.
- Власник проєкту — не програміст; обрано найпростіший безкоштовний варіант (ліміт Web3Forms — ~250 заявок на місяць). Не переходь на інший сервіс без запиту. Access Key Web3Forms можна тримати у фронтенді, але секретні токени (Telegram-бот, SMTP тощо) — ніколи.
- Сервіс обробки згадано в `privacy.html` (розділ 3). При зміні сервісу онови цей текст.

## Дані, що дублюються (оновлювати синхронно!)

Деякі дані записані в кількох місцях. Змінюючи їх, онови **всі** входження:

- **Графік роботи**: таблиця `.hours` в `index.html`, `openingHoursSpecification` у JSON-LD в `<head>`, `CONFIG.hours` у `main.js`.
- **Телефон** `+380501234567`: JSON-LD, кнопка `nav__call`, блок контактів (`tel:` і видимий текст), посилання Viber.
- **E-mail** `info@mobipoint.example`: JSON-LD, контакти, `privacy.html`.
- **Адреса** (Кременчук, вул. Соборна, 10): JSON-LD, контакти, посилання «Прокласти маршрут» (URL-кодована), `bbox` карти OSM.
- **Домен** `https://example.com/`: `canonical`, `og:image`, JSON-LD `url`, `robots.txt`, `sitemap.xml`. При зміні сторінок онови `lastmod` у `sitemap.xml`.
- **Кількість** у лічильниках `data-count` (напр. 12 брендів) має відповідати реальному контенту.

## Галерея та зображення

Зараз плитки — це `<span class="ph ph--N">емодзі</span>` з градієнтним фоном. Щоб поставити реальне фото (інструкція також є в коментарі в HTML):

```html
<li class="gallery__item" data-category="products">
  <button type="button" class="gallery__btn" data-caption="Опис" data-full="assets/img/gallery/photo-large.webp">
    <img src="assets/img/gallery/photo.webp" alt="Опис" loading="lazy" width="600" height="450">
    <span class="gallery__cap">Підпис</span>
  </button>
</li>
```

Категорії фільтра: `products`, `store` (таб `all` показує все). Нова категорія = нова кнопка `.tab[data-filter]` + відповідні `data-category`. Lightbox сам підхоплює `img` або `.ph` і гортає лише видимі (відфільтровані) елементи.

Для команди: замість `.person__photo` з ініціалами можна вставити `<img>` всередині `.person` — стилі для `.person img` вже є.

## Доступність і SEO (не погіршувати)

- Є skip-link, `:focus-visible`, `aria-expanded`/`aria-controls` на бургері та акордеоні, `role="tablist"/"tab"` + `aria-selected` на табах, `role="dialog"` + `aria-modal` на lightbox, `aria-live` на статусах, `sr-only` caption у таблиці. Нові інтерактивні елементи мають бути доступні з клавіатури й мати українські `aria-label`.
- Декоративні елементи — `aria-hidden="true"`.
- Один `<h1>` на сторінку, далі `h2` у секціях, `h3` у картках.
- У `<head>`: `title`, `description`, `canonical`, Open Graph, `theme-color`, JSON-LD `Store`. Зберігай їх актуальними. `privacy.html` має `noindex`.
- Зовнішні посилання — `target="_blank" rel="noopener"`.

## Відомі недоліки та заглушки

Це не баги, які треба мовчки виправляти, а місця, які варто узгодити з користувачем:

- `<h1>` у hero містить «Кременчуцький національний університет» — не відповідає тематиці магазину (можливо, вимога навчального завдання). **Не змінюй без підтвердження**.
- Плейсхолдери: домен `example.com`, e-mail `@mobipoint.example`, посилання Telegram `https://t.me/` без юзернейму, відсутній `assets/img/og.jpg`, демо-телефон, вигадані імена співробітників.
- Описки в тексті: «Обмін надійного товару» (ймовірно, «якісного»), «8 000 наклеєних скол» (має бути «стекол»).
- Текст умов обміну/повернення та `privacy.html` — шаблони, позначені як такі; юридичні формулювання не вигадуй — пропонуй, а остаточне рішення за користувачем.
- `privacy.html` використовує загальний `style.css`, але заголовки `h1/h2` там без окремого оформлення (через скидання `margin: 0`).
- Логотипи брендів — текстом; справжні логотипи ставити лише за наявності дозволу.

## Чекліст перевірки після змін

1. Сторінка відкривається без помилок у консолі браузера.
2. Ширини ~375px, 768px, 1024px+: немає горизонтального скролу, меню-бургер працює на мобільному, десктопне меню — з 1024px.
3. Світла й темна тема (`prefers-color-scheme`) — текст читається, контраст збережено.
4. Клавіатура: Tab по всіх інтерактивних елементах, видимий фокус, Esc закриває меню й lightbox.
5. Галерея: фільтр, відкриття lightbox, гортання стрілками.
6. Акордеон відкриває по одному пункту.
7. Статус «відчинено/зачинено» і підсвітка сьогоднішнього дня коректні.
8. Форма: порожня відправка показує помилки; валідна з вказаним `web3formsKey` — повідомлення про успіх і лист на пошті (без ключа — повідомлення про помилку).
9. Якщо змінювались контакти/графік/домен — перевір усі місця зі списку «Дані, що дублюються».

## Як працювати агенту

- Вноси мінімальні точкові правки в наявні файли; не створюй нових CSS/JS-файлів без потреби — усе живе в `style.css` і `main.js`.
- Зберігай стиль коду, структуру коментарів-роздільників і українську мову текстів.
- Перед зміною контактних даних, цін, юридичних умов чи імен — уточнюй у користувача, не вигадуй «правдоподібні» значення.
- Не публікуй сайт, не підключай сторонні сервіси (аналітика, чат-віджети, CRM) і не додавай трекери без явного запиту.
